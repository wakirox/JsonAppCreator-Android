# JSON App Creator

[![CI](https://github.com/wakirox/JsonAppCreator-Android/actions/workflows/ci.yml/badge.svg?branch=master)](https://github.com/wakirox/JsonAppCreator-Android/actions/workflows/ci.yml)

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

JSON App Creator is an Android interpreter that turns a JSON configuration into a
native, interactive app. Configurations can define layouts, text, images, lists,
forms, navigation, alerts, data binding, and REST requests without creating another
Android project.

The current format is **v3**. It is designed to be written by people or generated by
LLMs, then validated before the app loads it.

## Features

- Vertical and horizontal Jetpack Compose layouts
- Text, buttons, remote images, static lists, and API-backed lists
- Text, numeric, email, password, date, selector, and checkbox form fields
- Click and long-click actions
- Reusable views and actions with explicit references
- GET and POST requests with chained navigation or alert events
- Dot-path data binding and `${placeholder}` interpolation
- In-app JSON Schema and semantic reference validation
- Isolated runtime data for every opened screen

## Download

Download the latest signed APK and its SHA-256 checksum from
[GitHub Releases](https://github.com/wakirox/JsonAppCreator-Android/releases/latest).
The app requires Android 8.1 (API 27) or newer.

## Try it

The app opens on **Masterpieces**, an example gallery of public-domain paintings. From the
three-dot menu:

- **New app** starts a small app in the built-in editor; **Edit configuration** opens the
  active one. The editor colours the JSON, suggests the properties and values the schema
  allows where the cursor is, checks the file as you type (tap a problem to jump to it),
  inserts ready-made views from **+**, and **▶** runs the result. **Save as file…** exports it.
- **Load configuration from device** opens a UTF-8 JSON file in the v3 format.
- **Ask an AI to make an app** copies a complete prompt, or shares it as a Markdown file,
  for ChatGPT, Claude, Gemini or any other assistant: the rules, a reference of every
  view, field and event generated from the schema, worked examples and your request
  (optionally with the current app to change). In the editor, **Paste AI answer** takes
  the JSON out of the reply, and **Copy problems for AI** sends the check's findings back.

The app validates the complete file before saving or displaying it. Invalid files show
path-based feedback such as `$.mainView.views[1].type`. The last valid configuration
remains saved.

Configurations may use named API-key placeholders such as `__TMDB_API_KEY__`. When a
loaded file contains one, the app asks for the value and encrypts it in private app
storage, scoped to that exact JSON file. The key is never inserted into the saved JSON.

Android can also offer JSON App Creator when another app opens an `application/json`
file. Use **Edit configuration** to see or change the active JSON.

## Minimal configuration

```json
{
  "schemaVersion": 3,
  "name": "Hello JSON",
  "author": "Your name",
  "version": "1.0.0",
  "mainView": {
    "type": "layout",
    "views": [
      {
        "type": "text",
        "label": "Hello!",
        "title": "This screen was created from JSON.",
        "textStyle": "bold",
        "textSize": 20
      }
    ]
  }
}
```

Save it as `hello.json` and load it from the app.

New configurations should include `"schemaVersion": 3` and use explicit references:

```json
{ "ref": "details" }
```

Legacy ID-only references such as `{ "id": "details" }` remain supported, but explicit
`ref` objects are unambiguous and preferred.

## Validate a configuration locally

The same structural validator used by the Android app is available through Gradle:

```sh
./gradlew :app:validateConfig -Pconfig=path/to/my-app.json
```

Validation checks the v3 JSON Schema as well as every bundled v3 configuration. The
Android parser additionally checks unresolved references, duplicate IDs, mixed
reference/definition objects, invalid IDs, and view-containment cycles.

## Build from source

Requirements:

- JDK 17
- Android SDK with API 36 installed
- An Android device or emulator running API 27+

Build the debug APK:

```sh
./gradlew assembleDebug
```

The APK is written to `app/build/outputs/apk/debug/app-debug.apk`.

Bundled configurations can receive placeholder values from an untracked Java
properties file outside the repository. Each property is scoped by raw-resource name:

```properties
v3_the_movie_db.TMDB_API_KEY=<your-own-key>
```

Point Gradle to it through the environment or a Gradle property:

```sh
APP_CONFIG_KEYS_FILE=/secure/path/config-keys.properties ./gradlew :app:assembleDebug
# or: ./gradlew :app:assembleDebug -PconfigApiKeysFile=/secure/path/config-keys.properties
```

GitHub Actions builds can use a repository secret named `TMDB_API_KEY` directly. Add
it under **Repository settings → Secrets and variables → Actions → New repository
secret**; both the CI and release workflows pass it to Gradle. For multiple bundled
configurations, CI can instead set `APP_CONFIG_KEYS_BASE64` to Base64-encoded
properties content. If both contain a TMDB value, `TMDB_API_KEY` takes precedence.
Key values are not logged, but build-time credentials are compiled into the APK and
can be extracted. Use restricted, non-privileged keys and rotate them if exposed.

Run all unit and screenshot tests:

```sh
./gradlew testDebugUnitTest
```

Run the configuration-focused tests:

```sh
./gradlew testDebugUnitTest \
  --tests '*ConfigurationValidatorTest' \
  --tests '*ConfigSchemaValidationTest' \
  --tests '*AppParserReferenceTest'
```

## Automation

Pushes to `master` run the complete unit and screenshot suite, validate a public
configuration, and build a short-lived debug APK artifact. Tags such as `v1.0.0` run
the same checks before producing a signature-verified release APK and checksum.

Release signing setup, version derivation, tagging, verification, and key recovery are
documented in [the release guide](docs/RELEASING.md).

## Project structure

```text
schema/                            Versioned machine-readable contracts
docs/                              Configuration and LLM documentation
examples/                          Small focused v3 configurations
app/src/main/java/.../model/       JSON-backed application definitions
app/src/main/java/.../validation/  Runtime schema validation
app/src/main/java/.../runtime/     Per-screen runtime state
app/src/main/java/.../ui/          Jetpack Compose renderer
app/src/main/res/raw/              Bundled sample configurations
app/src/test/                      Parser, validator, state, and screenshot tests
samples/                           Shareable APK and full configuration example
```

The app is written in Kotlin and rendered with Jetpack Compose. JSON is parsed with
Jackson, JSON Schema validation uses NetworkNT, HTTP requests use OkHttp, and remote
images are loaded with Glide. Gradle configuration uses Kotlin DSL.
