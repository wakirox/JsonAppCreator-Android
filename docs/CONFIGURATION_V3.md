# Appkin v3 Configuration Reference

[Back to the project README](../README.md) · [LLM generation guide](LLM_GUIDE.md) ·
[JSON Schema](../schema/v3.schema.json)

Appkin is an Android app that turns a JSON configuration into a native,
interactive interface. A configuration can describe layouts, text, images, lists,
forms, navigation, alerts, and REST requests without creating a new Android project.

The format is intentionally compact enough to be written by hand or generated by an
LLM. This README documents the currently supported **v3 configuration format**.

## What it can build

- Vertical and horizontal layouts
- Text, buttons, and remote images
- Static or API-backed lists, and lists of what the app saved on the phone
- Forms with text, numeric, email, password, date, selector, and checkbox inputs
- Click and long-click actions
- Screen-to-screen navigation
- GET and POST requests with chained events
- Saving, changing and deleting entries on the phone, per app, with tick boxes for done items
- Alerts with optional confirmation branches
- Reusable views and actions referenced by ID
- Data binding through dot paths and `${placeholder}` interpolation

## Try it

Install [Appkin from Google Play](https://play.google.com/store/apps/details?id=it.sapienza.androidratio.appratio).
It needs Android 13 (API 33) or newer.

1. Write a UTF-8 JSON file using the format below.
2. Open Appkin, open the three-dot menu on its home page, tap **Open a file…**
   and choose the file. Android can also offer Appkin when you open an
   `application/json` file from another app.
3. Inside the app, its three-dot menu has **Edit this app** to see or change the JSON.
   **New app** on the home page starts one from scratch in the built-in editor.

Every app you open or edit is kept under **Your apps** on the home page.

The home page also lists the bundled examples: Art Explorer, Masterpieces, Hello, Summer
Run, and The Movie DB. Their source is under
[`app/src/main/res/raw`](../app/src/main/res/raw); the most complete one is
[`samples/v3_the_movie_db.json`](../samples/v3_the_movie_db.json).

## Minimal configuration

Save this as `hello.json` and load it from the app:

```json
{
  "schemaVersion": 3,
  "name": "Hello JSON",
  "author": "Your name",
  "version": "1.0.0",
  "mainView": {
    "type": "layout",
    "views": [
      {
        "type": "text",
        "label": "Hello!",
        "title": "This screen was created from JSON.",
        "textStyle": "bold",
        "textSize": 20
      }
    ]
  }
}
```

`schemaVersion`, `name`, `version`, and `mainView` are required for new configurations.
The validator accepts a missing `schemaVersion` only for backward compatibility.
`author`, `icon`, `changelog`, `debugMode`, `views`, and `actions` are optional.

## Configuration model

### Application

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `schemaVersion` | integer | yes for new files | Must be `3`. Omission is supported only for legacy files. |
| `name` | string | yes | Title displayed in the app bar. |
| `version` | string | yes | Version displayed in the app menu. |
| `mainView` | view | yes | First screen. Usually an inline `layout`. |
| `author` | string | no | Author displayed in the app menu. |
| `changelog` | string | no | Adds a menu item that opens this text. |
| `icon` | string | no | One emoji for the app's icon on the home page and the home screen, such as `"🏍️"`. Without it, the icon is the name's first letter. |
| `debugMode` | boolean | no | Reserved; currently has no visible behavior. |
| `views` | view[] | no | Reusable views. Give every entry a unique `id`. |
| `actions` | action[] | no | Reusable actions. IDs must be unique. |

Unknown or incorrectly cased enum values fail parsing. Use the lowercase values shown
in this document.

### Properties shared by views

All views may contain:

| Property | Type | Description |
| --- | --- | --- |
| `type` | string | `layout`, `text`, `button`, `image`, `list`, or `form`. Omit only in a reference object. |
| `id` | string | Identifier used to reuse or navigate to the view. |
| `action` | action | Inline action or `{ "ref": "action_id" }` reference. |
| `mapping` | string | Dot path read from the current data object. Meaning varies slightly by view type. |
| `data` | object | Local data. It overrides inherited data for this node and its children. |
| `visibleIf` | string | A path in the view's data: the view is shown only when there's a value there. See [Showing views only with data](#showing-views-only-with-data). |

### `layout`

A layout groups child views.

```json
{
  "type": "layout",
  "orientation": "horizontal",
  "views": [
    { "type": "text", "title": "Left" },
    { "type": "text", "title": "Right" }
  ]
}
```

- `views` is an array of child views.
- `orientation` is `vertical` by default; it may also be `horizontal`.
- Children without an explicit width share the available space in a horizontal layout.

### `text`

```json
{
  "type": "text",
  "label": "Display name",
  "mapping": "profile.name",
  "textStyle": "bold",
  "textSize": 18,
  "size": { "width": 240, "height": 60 }
}
```

| Property | Type | Description |
| --- | --- | --- |
| `title` | string | Literal or interpolated text. Used when `mapping` produces no value. |
| `label` | string | Optional text displayed before/above the value. Supports interpolation. |
| `mapping` | string | Reads the displayed value from the current data object. |
| `textStyle` | string | `regular` (default), `italic`, or `bold`. |
| `textSize` | number | Text size in scale-independent pixels (sp). |
| `size` | object | Optional `width` and `height`, interpreted as density-independent pixels (dp). |
| `labelStyle` | string | The label's weight and slant: `regular`, `italic` or `bold`. By default the label is a semi-bold heading, and the text under it a quieter supporting line. |
| `format` | string | `plain` (default) or `html`: the text is simple HTML (`<b>`, `<i>`, `<em>`, `<strong>`, `<u>`, `<br>`, `<p>`, `<a href>`). |
| `showWhenEmpty` | boolean | Keep the label when `mapping` (or `title`) has nothing to show. `false` by default: such a text view isn't drawn, label included. |

A text view with an `action` shows an arrow at its end, so it reads as something to tap.
Buttons on their own are tonal; a form's submit button is the filled one, at the form's
end.

A text view whose `mapping` finds no value, or whose `title` is empty once its placeholders are
filled in, isn't drawn at all, so a missing "Technique" doesn't leave its label behind. A text
view with only a `label` is a heading and is always drawn.

### `button`

A button supports the text properties above and normally includes an `action`.

```json
{
  "type": "button",
  "title": "Open details",
  "action": { "ref": "show_details" }
}
```

`icon` adds an icon from the phone's standard set: `add`, `check`, `close`, `delete`,
`edit`, `email`, `favorite`, `info`, `phone`, `place`, `refresh`, `search`, `settings`,
`share` or `star`. With a `title` it sits before the text; without one the button is just
the icon, keeps its small size and sits centred in a row, and `label` (supports `${...}`)
is what screen readers say:

```json
{ "type": "button", "icon": "delete", "label": "Delete ${title}", "action": { "ref": "delete_idea" } }
```

### `image`

```json
{
  "type": "image",
  "url": "https://example.com/images/${profile.id}.jpg",
  "size": { "width": 120, "height": 180 }
}
```

- `url` is the fallback/static image URL and supports `${...}` interpolation.
- `mapping` may instead read the complete URL from the current data object.
- `size.width` and `size.height` are dp. The default height is 220 dp.
- `scale` is `crop` (default: the picture fills its space and its edges may be cut) or
  `fit` (the whole picture shows, inside its space).
- Tapping an image without an action opens its full-screen preview. Images inside list
  cards do not open a preview unless the surrounding list/card supplies navigation.
- Use HTTPS URLs. Cleartext HTTP traffic is disabled.

### `list`

A list repeats `itemView` once for every object in a JSON array.

```json
{
  "type": "list",
  "orientation": "vertical",
  "mapping": "results",
  "initData": {
    "url": "https://api.example.com/items",
    "method": "get"
  },
  "action": { "ref": "show_item" },
  "itemView": {
    "type": "layout",
    "orientation": "horizontal",
    "views": [
      {
        "type": "image",
        "mapping": "thumbnail",
        "size": { "width": 96, "height": 96 }
      },
      {
        "type": "text",
        "mapping": "title"
      }
    ]
  }
}
```

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `itemView` | view | yes | Template rendered for every array item. |
| `mapping` | string | yes in normal use | Dot path to the array in the response or inherited `data`. |
| `initData` | REST service | no | Fetches the list data when the list appears. |
| `stored` | stored data | no | Shows what the app saved on the phone; see [Save on the phone](#save-on-the-phone). Not with `initData`. |
| `orientation` | string | no | `vertical` (default), `horizontal`, or `grid`: items side by side in rows. |
| `columns` | integer | no | Items per row of a `grid`, 1 to 6; 2 by default. |
| `emptyText` | string | no | What the list says when it has no items, instead of "No data available". Supports `${...}`. |
| `action` | action | no | Runs with the tapped item as its data payload. |

The response must be a JSON object, and the selected array must contain JSON objects.
For local data, place an array in a parent or list `data` object and select it with
`mapping`:

```json
{
  "type": "list",
  "mapping": "items",
  "data": {
    "items": [
      { "name": "One" },
      { "name": "Two" }
    ]
  },
  "itemView": { "type": "text", "mapping": "name" }
}
```

#### More pages

A list loaded with `initData` can keep loading as it's scrolled: `initData.nextPage` says how
to ask for the next page.

```json
"initData": {
  "url": "https://api.example.com/works?q=${q}&limit=40",
  "nextPage": { "parameter": "skip", "step": 40 }
}
```

With `parameter` and `step`, the next page's URL is the last one with that query parameter
grown by `step` (from its value in the URL, or 0), until a page has fewer than `step` items:
make `step` the page size. With `"urlFrom": "info.next"` instead, the next page's URL is the
response's value at that path, until there is none. A list that fills the screen loads its
next page when its end comes into view; a list inside a screen that scrolls as a whole shows
a "Show more" button. A list loads 50 pages at most.

Pulling a screen down loads its `initData` lists again, from their first page.

### `form`

```json
{
  "type": "form",
  "title": "Create account",
  "buttonTitle": "Continue",
  "formElements": [
    {
      "type": "text",
      "mapping": "user.email",
      "title": "Email",
      "placeholder": "name@example.com",
      "textType": "email",
      "mandatory": true
    },
    {
      "type": "selector",
      "mapping": "user.role",
      "title": "Role",
      "options": ["Reader", "Editor"],
      "mandatory": true
    },
    {
      "type": "checkbox",
      "mapping": "accepted",
      "title": "Accept terms",
      "value": false,
      "mandatory": false
    }
  ],
  "action": {
    "id": "submit_account",
    "type": "click",
    "event": {
      "type": "rest",
      "url": "https://api.example.com/accounts",
      "method": "post"
    }
  }
}
```

Form submissions build a JSON object from each element's `mapping`, including nested
objects for dot paths, and pass that object to the action.

Supported form elements:

| `type` | Main properties |
| --- | --- |
| `text` | `mapping`, `title`, `description`, `placeholder`, `value`, `mandatory`, `textType` |
| `selector` | `mapping`, `title`, `description`, `options`, `selection`, `mandatory` |
| `date` | `mapping`, `title`, `description`, `value`, `min`, `max`, `mandatory` |
| `checkbox` | `mapping`, `title`, `description`, `value`, `mandatory` |
| `time` | `mapping`, `title`, `description`, `value` (`HH:mm`), `mandatory` |
| `hidden` | `mapping`, `value` |

`textType` is `plain` (default), `numeric`, `email`, or `password`. Dates shown through
mapped form data use `dd/MM/yyyy`. `mandatory: true` blocks submission until a text
(not just spaces), selector, or date value is set, or a checkbox is checked; the error
names the missing fields. Without `mandatory`, a field is optional. Values filled in from
the screen's data count as set and are submitted.

A selector's `options` are strings, each shown and submitted as it is, or objects that
show one thing and submit another:

```json
"options": [ { "label": "Any type", "value": "" }, "Painting", "Print" ]
```

`selection` and values from the screen's data are option values, not labels.

A `time` field opens a clock and submits `HH:mm` on a 24-hour clock, which a calendar
event's `time` takes: `"time": "${time}"`.

A `hidden` field isn't shown; it sends `value` with the form, with placeholders filled in
from the screen's data, such as `{ "type": "hidden", "mapping": "id", "value": "${id}" }`.
Without `value` it sends the screen data's value at `mapping`. Its value is sent as text.

In a request URL, a query parameter that is a single placeholder, such as
`&type=${type}`, is optional: when that value is missing or empty (an optional field left
blank, or an "Any type" option with the value `""`), the parameter is left out rather than
sent empty.

### `check`

A tick box for a true/false field of the data, with an optional `title` (supports
`${...}`). Ticking it runs `action` with the value at `mapping` turned over; see
[Change or delete saved data](#change-or-delete-saved-data).

## Data binding

Each rendered node receives a current JSON data object:

- A node's own `data` replaces inherited data for that node and its descendants.
- A list item receives that item object as its data.
- A REST response becomes the data passed to its chained event.
- A `show` event passes its current data to the view it opens, or only the part its
  `mapping` selects, such as `meals.0` for the one item of a lookup response.
- A form action receives the object assembled from the submitted fields.
- An action's own `data`, when present, replaces the data from the clicked view.

Use a dot path in `mapping` to read nested data:

```json
{ "type": "text", "mapping": "profile.address.city" }
```

Use `${path}` inside `title`, `label`, image `url`, REST `url`, or alert `value` to
interpolate data:

```json
{
  "type": "text",
  "title": "${profile.name} lives in ${profile.address.city}."
}
```

Dot paths traverse JSON objects, and reach array items by index: `meals.0.strMeal` and
`meals[0].strMeal` are the same. A list's `initData` URL can use placeholders too, filled
from the data of the screen it is on. Array values used as text are joined with `, `.

A placeholder with no value (missing or `null`) becomes empty text: `"By ${artist}"` reads
`By ` when there's no `artist`. Addresses are different. A REST `url` (an event's or a list's
`initData`) with a placeholder that has no value isn't requested at all: the app says what's
missing, such as "This item has no creators.0.id", instead of asking for the wrong address.
An image whose `url` has a placeholder with no value shows "Image unavailable".

In a REST `url`, an `initData` URL or an image `url`, each value a placeholder inserts is
percent-encoded, so `?type=${type}` with `arms & armor` requests `?type=arms%20%26%20armor`
and a value can't add parameters of its own. The rest of the address is used exactly as
written, so encode any fixed text in it yourself (`department=Japanese%20Art`). A placeholder
that starts the address, such as `"url": "${images.web.url}"`, supplies a whole address and
is used as it is.

### Showing views only with data

Any view, and a `{ "ref": … }` reference, can have `visibleIf`: a path in the view's data. The
view is shown only when there's a value at that path that isn't `null`, empty text, `false`,
`0`, or an empty array or object. Start the path with `!` for the opposite: shown only when
there's no such value. A view that isn't shown takes no space.

```json
[
  { "type": "text", "label": "Artist", "mapping": "creators.0.description", "visibleIf": "creators" },
  { "type": "text", "title": "Artist unknown", "visibleIf": "!creators" },
  { "type": "button", "title": "Plan a visit", "visibleIf": "current_location", "action": { "ref": "plan_visit" } }
]
```

`visibleIf` only tests whether a value is there: it has no comparisons or other expressions.

## Actions and events

An action may be declared inline or once in the root `actions` array and reused with an
explicit `ref` object.

```json
{
  "id": "show_details",
  "type": "click",
  "event": {
    "type": "show",
    "view": { "ref": "details" }
  }
}
```

Action properties:

| Property | Type | Required | Description |
| --- | --- | --- | --- |
| `id` | string | yes | Unique action identifier. |
| `type` | string | no | `click` (default) or `longclick`. |
| `event` | event | yes for a definition | Event to run. Omit it only in a reference. |
| `data` | object | no | Fixed payload that overrides the clicked/current data. |

### Show a view

```json
{
  "type": "show",
  "view": { "ref": "details" }
}
```

`view` can be a `ref` object targeting a root `views` entry or a complete inline view. The
current event data is passed to the destination view. Android's Back button returns to
the previous view.

`title` names the opened screen in the app bar, instead of the app's name. Its placeholders
come from the data the screen receives: `"title": "Works by ${name}"`.

### Add an event to the calendar

```json
{
  "type": "calendar",
  "title": "Dinner: ${cuisine}",
  "date": "${date}",
  "time": "19:30",
  "durationMinutes": 180,
  "location": "Home",
  "description": "${guests} guests, hosted by ${name}"
}
```

Opens the phone's calendar app on a new event, filled in; the user reviews and saves it
there, so the app needs no calendar permission. `date` is `dd/MM/yyyy`, as a form's
`date` field submits it, and `time` is `HH:mm`; without `time` the event lasts all day.
A timed event lasts `durationMinutes`, 60 by default. Every text may use `${...}`.

### Save on the phone

```json
{
  "type": "save",
  "collection": "ideas",
  "fields": { "appId": "${id}", "done": false },
  "thenDo": { "type": "alert", "value": "Saved ${title}" }
}
```

Saves the current data, usually a form's submitted values, as a new object of a
collection kept on the phone. Each app has its own collections, and they stay when the
app is closed or opened again from Your apps. Every object gets an `id` and a `createdAt`
(epoch milliseconds). `fields` adds values; their `${...}` placeholders are filled from
the data the form showed (the screen's, or its list row's), then from the submitted values.
`thenDo` runs with the saved object. A form saved this way starts empty again. With
`"unique": "key"`, an object already saved with the same `key` is replaced (keeping its
`id`) instead of added again, so a "Favourite" button can be tapped twice safely.

A list shows a collection with `stored` instead of `initData` or `data`:

```json
{
  "type": "list",
  "stored": { "collection": "ideas", "where": { "appId": "${id}" } },
  "itemView": { "type": "text", "mapping": "title" }
}
```

Objects appear oldest first unless `sort` says otherwise, and the list updates as soon as
one is saved, on this screen or another. `where` keeps only the objects whose fields have those values, with
placeholders from the list's data; so a details screen opened on an app with `id` shows
only that app's ideas. `mapping` is not used.

`sort` orders the list by a field. Values listed in `order` come first, in that order;
the others follow, numbers by size and text alphabetically, and objects without the field
come last. `"descending": true` turns the order round. Objects that tie keep the order
they were saved in:

```json
"stored": {
  "collection": "ideas",
  "where": { "appId": "${id}" },
  "sort": { "by": "priority", "order": ["High", "Medium", "Low"] }
}
```

Data is kept by the app's name: an app renamed in the editor starts with no saved data.

### Change or delete saved data

```json
{ "type": "update", "collection": "ideas", "fields": { "done": true } }
```

Changes the saved object whose `id` is the current data's (or the one `id` names, such
as `"${ideaId}"`): the current data and `fields` replace its values, and `thenDo` runs with
the changed object. `id` and `createdAt` never change. A form whose action is `update` sends
its values there and keeps them, so a screen opened on an item can edit it.

```json
{
  "type": "alert",
  "value": "Delete ${title}?",
  "thenDoOK": { "type": "delete", "collection": "ideas" }
}
```

Removes the saved object with the current data's `id`. With `where` instead, it removes
every object that matches, such as an app's ideas with `"where": { "appId": "${id}" }`;
chain the two with `thenDo` to delete an app and its ideas. Lists showing the collection
update at once.

A `check` view marks items done without a form: it is ticked when the data's value at
`mapping` is true, and ticking it runs its action with that value turned over. In a stored
list's `itemView`, an `update` saves it straight away, and a ticked title is struck through:

```json
{
  "type": "check",
  "mapping": "done",
  "title": "${title}",
  "action": { "id": "tick", "event": { "type": "update", "collection": "ideas" } }
}
```

### Open a link in another app

```json
{ "type": "open", "url": "${url}" }
```

Hands an address to the phone: `https:` and `http:` open the browser, `geo:` a map
(`geo:0,0?q=${address}`), `tel:` the dialer with the number filled in (nothing is called,
so the app needs no call permission) and `mailto:` an email app. Only these kinds of
address are opened; anything else, such as `javascript:` or `file:`, is refused with a
message. Placeholders work as in REST URLs: what they insert is percent-encoded, a
placeholder that starts the address may hold a whole address, and a missing value stops
the link with "This item has no …". `mapping` selects the part of the data to use.

### Share text

```json
{ "type": "share", "text": "${title}\n${url}" }
```

Opens the phone's share sheet on `text`, for the user to send to any app. A placeholder
with no value becomes empty text.

### Call a REST endpoint

```json
{
  "type": "rest",
  "url": "https://api.example.com/items/${id}",
  "method": "get",
  "thenDo": {
    "type": "show",
    "view": { "ref": "details" }
  }
}
```

- `method` is `get` (default), `post`, `put` or `delete`.
- `${...}` values in `url` come from the action's active data.
- POST and PUT send the active data as an `application/json` body.
- `headers` adds request headers. Their values may use `${...}` (a missing value stops the
  request, as in the URL) and API-key placeholders, which go in as they are:
  `"headers": { "Authorization": "Bearer __API_TOKEN__" }`. Appkin sets `User-Agent`,
  `Host`, `Content-Type` and `Content-Length` itself. A list's `initData` takes `method` and
  `headers` too.
- `thenDo` receives the JSON response object and may be any event. An empty answer, as a
  DELETE often gives, is an empty object.
- `onError` runs instead of the error alert when the request fails. Its data is the
  request's data plus `error.message` and, for an HTTP error, `error.status`:
  `"onError": { "type": "alert", "value": "Couldn't save ${name}: ${error.message}" }`.
- Only HTTPS, JSON-object response bodies, and successful HTTP `2xx` statuses are handled.
  JSON arrays at the response root are not supported.

#### API-key placeholders

Keep credentials outside configuration JSON by using an uppercase named placeholder
in a REST URL or header:

```json
{
  "type": "rest",
  "url": "https://api.example.com/items?api_key=__CATALOG_API_KEY__",
  "method": "get"
}
```

Names must match `__[A-Z][A-Z0-9_]*__`. They are distinct from `${path}` data
interpolation. When a JSON file is loaded from a device, the app prompts for every
key, encrypts the values with Android Keystore, and stores them in private app storage
under a SHA-256 identity for that exact JSON. The original JSON remains unchanged, so
viewing or sharing it does not expose the keys. Loading the same file again can reuse
or replace its saved values; changing the file gives it a separate identity.

For a bundled file in `app/src/main/res/raw`, builds can supply values from an external
Java properties file. Scope each entry with the raw-resource name:

```properties
v3_the_movie_db.TMDB_API_KEY=<your-own-key>
```

Set `APP_CONFIG_KEYS_FILE` to the file path, pass
`-PconfigApiKeysFile=/secure/path/config-keys.properties`, or provide Base64-encoded
properties content as `APP_CONFIG_KEYS_BASE64`. The bundled TMDB configuration also
accepts `TMDB_API_KEY` directly; GitHub Actions passes the repository secret with that
name to CI and release builds. A direct `TMDB_API_KEY` overrides the corresponding
value from the properties source. Keep source files outside the repository.
Build-time keys are embedded in the APK and are therefore recoverable by someone who
has the APK; only use restricted client keys.

An `initData` object on a list uses the same REST fields but does not need a `type`:

```json
{
  "url": "https://api.example.com/items",
  "method": "get"
}
```

### Show an alert

```json
{
  "type": "alert",
  "value": "Delete ${name}?",
  "thenDoOK": {
    "type": "rest",
    "url": "https://api.example.com/archive/${id}",
    "method": "post"
  },
  "thenDoKO": {
    "type": "show",
    "view": { "ref": "cancelled" }
  }
}
```

Use `value` for a literal/interpolated message, or `mapping` to read the message from
the current data. `thenDoOK` runs from the **OK** button. An alert with `thenDoOK` or
`thenDoKO` also shows a **Cancel** button, which runs `thenDoKO` when there is one and
otherwise just closes the alert, so a question such as "Add it to your calendar?" can be
declined.

## Reusing views and actions

Put shared destination views in root `views` and shared actions in root `actions`:

```json
{
  "schemaVersion": 3,
  "name": "Catalog",
  "version": "1.0",
  "mainView": {
    "type": "layout",
    "views": [
      {
        "type": "button",
        "title": "About",
        "action": { "ref": "open_about" }
      }
    ]
  },
  "views": [
    {
      "id": "about",
      "type": "layout",
      "views": [
        { "type": "text", "title": "Made from JSON." }
      ]
    }
  ],
  "actions": [
    {
      "id": "open_about",
      "type": "click",
      "event": {
        "type": "show",
        "view": { "ref": "about" }
      }
    }
  ]
}
```

Important reference rules:

- A preferred reference is an object containing only `ref`, for example
  `{ "ref": "about" }`.
- Legacy ID-only references such as `{ "id": "about" }` remain accepted.
- Define an action before referencing it conceptually; its physical order in the JSON
  does not matter.
- Every root action must contain an event, and root action IDs must be unique.
- Prefer complete `layout` objects for reusable root views. A layout definition must
  have at least one child.
- Do not give the same ID to unrelated views. View lookup returns the first match.
- Inline definitions can have IDs, but an ID is unnecessary unless another object will
  reference them.

## Complete API-backed example

This example loads users, opens the selected user, and binds nested response fields:

```json
{
  "schemaVersion": 3,
  "name": "User directory",
  "author": "Example",
  "version": "1.0.0",
  "mainView": {
    "type": "layout",
    "views": [
      {
        "type": "text",
        "label": "Directory",
        "title": "Select a user",
        "textStyle": "bold",
        "textSize": 22
      },
      {
        "type": "list",
        "mapping": "users",
        "initData": {
          "url": "https://api.example.com/users",
          "method": "get"
        },
        "action": { "ref": "load_user" },
        "itemView": {
          "type": "layout",
          "orientation": "horizontal",
          "views": [
            {
              "type": "image",
              "mapping": "avatar",
              "size": { "width": 88, "height": 88 }
            },
            {
              "type": "text",
              "label": "${name}",
              "mapping": "company.name"
            }
          ]
        }
      }
    ]
  },
  "views": [
    {
      "id": "user_details",
      "type": "layout",
      "views": [
        {
          "type": "image",
          "mapping": "avatar",
          "size": { "height": 280 }
        },
        {
          "type": "text",
          "mapping": "name",
          "textStyle": "bold",
          "textSize": 24
        },
        {
          "type": "text",
          "label": "Email",
          "mapping": "contact.email"
        }
      ]
    }
  ],
  "actions": [
    {
      "id": "load_user",
      "type": "click",
      "event": {
        "type": "rest",
        "url": "https://api.example.com/users/${id}",
        "method": "get",
        "thenDo": {
          "type": "show",
          "view": { "ref": "user_details" }
        }
      }
    }
  ]
}
```

The list endpoint in this example must return an object shaped like
`{ "users": [ ... ] }`. The detail endpoint must return one user object.

## Validate and troubleshoot a configuration

Before loading a generated file, check its JSON syntax:

```sh
jq empty my-app.json
```

Run the same v3 schema validator used by the Android app:

```sh
./gradlew :app:validateConfig -Pconfig=path/to/my-app.json
```

The app automatically runs schema validation followed by semantic reference validation
before it saves an imported configuration.

Common failures:

- **Parsing error:** check required root fields, spelling, enum casing, and referenced
  definitions. JSON does not allow comments or trailing commas.
- **Blank or missing text:** the `mapping` path is absent from the current data object.
- **Placeholder remains visible:** the `${path}` does not exist in the current data.
- **Empty list:** `mapping` does not point to an array, the array does not contain
  objects, or the endpoint response shape differs from the configuration.
- **REST error:** the endpoint is not HTTPS, does not return a successful `2xx` response, requires
  unsupported headers/authentication, or returns a root array/non-JSON body.
- **Tap does nothing:** the action reference is missing, its ID does not match a root
  action, or the action definition has no event.
- **Destination does not open:** the view ID is missing or does not match a reusable
  view definition.

Use the app menu's **Edit this app** command to confirm which JSON is currently
loaded; its live check shows the same problems the app reports when loading.
